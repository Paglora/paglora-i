# Paglora Installer (paglora-i)

Standalone Windows installer shell for [Paglora Studio](https://github.com/m1nsook/paglora).

## Architecture

- **Wails v2 and Go:** native Windows UI bridge and validated installer launcher.
- **Svelte 5, TypeScript and CSS:** accessible Paglora-branded interface.
- **Tauri 2 NSIS:** performs the real install, registers Windows shortcuts and uninstaller.
- **Tauri updater inside Paglora:** retains the existing signed update flow. This repository never substitutes its own update format or signing keys.

The Wails application embeds a **version-pinned NSIS setup generated by Paglora's Tauri build**. Go checks the file's size and SHA-256 before invoking the documented NSIS `/S` silent setup switch. The Windows registry, uninstall functionality and Tauri updater remain entirely controlled by the existing NSIS package.

BetterDiscord/Installer provided an architectural reference (Wails + Go + Svelte). No BetterDiscord code or assets are copied.

## Develop (Windows)

Install Go, Bun, and the Wails v2 CLI; Windows needs WebView2. Use GitHub Desktop rather than Git CLI.

Run in PowerShell from this repository:

```powershell
cd frontend
bun install
bun run check
bun run build
cd ..
go test ./internal/installer/...
wails dev
```

Without a real packaged Paglora NSIS executable, the UI runs in **preview mode** and the Install action is intentionally disabled. This is also how its preview-only CI binary works.

## Package an actual Paglora installer

First build the **Paglora** repository's own NSIS target. Confirm that the same version also generates Tauri updater artifacts.

From `paglora-i`:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\package.ps1 -PagloraRepository "C:\path\to\paglora"
```

For a local test with an unsigned Tauri installer, explicitly add `-AllowUnsignedDevelopment`. Never distribute such an installer as stable.

Packaging checks the Paglora version and NSIS configuration, embeds the existing installer under `payload/`, writes a version-locked checksum manifest, builds the Wails app, and produces `build/bin/Paglora-Installer.exe`. The binary payload is ignored by Git.

**Important:** checksum verification prevents accidentally running mismatched installer bytes, but it isn't a digital signature. A public release requires valid Windows Authenticode signing and preserved Tauri updater signatures.

## Real Windows integration tests

The separate **Real Windows NSIS integration (development only)** GitHub Actions workflow tests a real, source-built Tauri NSIS executable on a disposable Windows runner. It:

1. Checks out the actual Paglora Desktop source, builds the Rust NSIS package and preserves the production updater configuration. It uses a *CI-only* override to skip generating signed updater artifacts; this is never applied to the Paglora repository.
2. Runs the packaging PowerShell script, embedding that precise setup executable into the branded Wails launcher. The bundle checksum and version are verified.
3. Uses an opt-in Go integration test to invoke the actual Tauri NSIS silently, checks Windows' current-user uninstall registration and Paglora application executable, then invokes the official NSIS uninstaller.
4. Keeps all temporary unsigned binaries inside the runner. It does **not** publish them or use production signing secrets.

Integration is triggered on changes to the installer handoff and can also be run using **Actions → Real Windows NSIS integration → Run workflow**. The normal validation workflow remains quick.

**Passing this test does not prove updater compatibility or Authenticode trust.** Production release still requires signed updater artifacts, Windows code signing, and a real old-to-new updater test. Never use the CI-only unsigned build as a public download.
